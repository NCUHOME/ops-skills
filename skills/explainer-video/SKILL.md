# 做视频（品牌库）

完整流程分六步：准备工作区 → 选要做什么 → 列材料 → 用户发材料 → 制作、审片 → 新建了品牌时问要不要存进品牌库。

- 视频引擎是 NCUHOME/explainer-kit（一个 Remotion 项目）。
- 所有命令都在**工作区**（引擎所在文件夹）的根目录运行。
- 每个信息点都要有画面把它“演”出来，不做会动的 PPT。

## 第一步：准备工作区

```bash
bash <本 skill 目录>/scripts/workspace.sh            # 最后一行输出工作区路径
bash <本 skill 目录>/scripts/workspace.sh <路径>     # 用户想把引擎放在别处时
```

- 脚本按这个顺序找工作区：当前文件夹 → 当前文件夹下的 `explainer-kit/` → 环境变量 `EXPLAINER_KIT` → `~/explainer-kit`。
- 都没有，就下载引擎并运行 `setup.sh`。第一次约 2 分钟；缺 Node、ffmpeg 或 Python 时，按提示让用户安装。

开工前，先读工作区里这三份文档：

- `docs/STYLE.md`：视觉规范；
- `docs/COMPONENTS.md`：组件用法；
- `docs/LESSONS.md`：用户审片意见，**每一条都是硬性要求**。

## 第二步：选要做什么

如果用户第一条消息已经说清楚（例如「继续做第八期」「用这份文档做一期，品牌用教务处」），就跳过这一步。

否则用选择题问。有 AskUserQuestion 就用它，没有就用文字列出编号。可以一次问两道题：

1. **要做什么**：做新一期 / 改已有一期或继续上次 / 只重新导出 / 新建品牌（换单位、栏目）。
2. **用哪个品牌**（做新一期时才需要）：
   - 先运行 `python3 tools/brand.py gallery -o 品牌一览.html`，把品牌一览网页打开给用户看；
   - 选项最多列 3 个品牌，写成「编号 名称」，最后一项固定为「新单位 / 栏目品牌」；
   - 品牌超过 3 个时，告诉用户可以在「其他」里填编号。`brand.py list` 能列出全部。

选「改已有一期」或「继续上次」时，先列出工作区里已有的期，让用户选：期数和标题看 `video/src/episodes/*/episode.json`，是否已有成片看 `out/`。

## 第三步：列出需要的材料

一条消息说完，然后等用户在**同一个对话的下一条消息**里发来。

| 要做的 | 需要的材料 |
|---|---|
| 做新一期 | ① 文档（.docx / .pdf / .txt），以及这期做哪一章 ② 期数和篇名 ③ 完整标题 ④ 封面副标题 ⑤ 截图、照片（可选）⑥ 口径：文档里说法矛盾的地方以哪个为准 ⑦ 要不要先看分镜 ⑧ 偏好，如时长、声音（可选） |
| 新建品牌 | ① 单位、部门（中英文）② 栏目名 ③ 两张组合标志：浅色底用的、深色底用的反白版（没有就用文字代替）④ 品牌主色 ⑤ 片尾免责声明 ⑥ 品牌名（小写英文，如 `ncu-xgc`）⑦ 标志能不能放进公开的品牌库 |
| 改已有一期 | 哪一期，以及修改意见：时间点或镜头、哪里不对、想要什么效果。有截图更好 |
| 只重新导出 | 哪一期；要不要压缩版 |

## 第四步：制作和审片

- **新建品牌**：
  1. 在工作区建 `brands/<品牌名>/`：从 `brands/ncu-jwc/` 复制过来改；字段说明在 `tools/brand.py` 开头。
  2. 放好标志图片，运行 `python3 tools/brand.py check`，必须全部通过。
  3. 渲染一张封面帧给用户确认：
     ```bash
     python3 tools/brand.py use <品牌名>
     cd video && npx remotion still EP-<任意一期> /tmp/封面.png --frame=<封面帧> --scale=0.5
     ```
     封面帧从那一期的 `timeline.json` 里 `section` 为 `cover` 的镜头算。
- **做新一期、修改、导出**：严格按 `references/PRODUCTION.md`。新建一期时带上品牌：`new_episode.py <id> … --brand <品牌名>`。
- 交付时要告诉用户的内容，见 `PRODUCTION.md` 最后一节。

## 第五步：存进品牌库（只有这次新建了品牌才问）

用现成品牌做的，不要问。

新建了品牌的，交付完问：「这个品牌要存进品牌库吗？存进去以后大家都能选。」用户同意后，按 `references/CONTRIBUTE.md` 向 NCUHOME/explainer-kit 提 PR。

- **只提 PR，由维护人审核合并，绝不直接推到 main。**
- 只提交品牌文件夹。用户自己做的期（`video/src/episodes/`、`index.ts`）可能有没公开的内容，不要提交。
- 用户提出的、对每一期都适用的审片意见，追加到工作区的 `docs/LESSONS.md`，问用户要不要一起提 PR。

## 硬性要求

- **答案只能来自原文。** 改写处、合并处、从其他章节补进来的句子，都要在交付时逐条列出请用户核对。不要加原文没有的推断，例如原文只说「APP 不受理」，就不能写成「线下办理」。
- 文档里有前后矛盾，列出来问用户以哪个为准，不要自己选。
- 示意数据（例如成绩卡上的分数）要标明「示意」。
- 渲染完整视频约 10 分钟，要放到后台运行。交付前必须用 `tools/review.sh` 截帧自查。
- 声音你听不到。交付时请用户亲自听一遍。
