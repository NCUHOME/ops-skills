# 制作细则

所有命令都在工作区根目录运行。规范文件都在工作区的 `docs/` 里：

- `docs/STYLE.md`：视觉规范；
- `docs/COMPONENTS.md`：组件用法；
- `docs/LESSONS.md`：用户审片意见，属于硬性要求；
- `docs/CHECKLIST.md`：自查清单。

## 1. 读文档

- 用 `tools/doc2text.sh <文件>` 把文档转成文字，然后通读一遍。
- 截图、照片放到 `video/public/img/`。
- 文档里有前后矛盾（例如 APP 有某个入口，但文件说不受理）：列出来问用户以哪个为准，不要自己选。

## 2. 拆集与内容

- **一集对应文档的一个章节**。一集 2–3 分钟最合适，超过 4 分钟就拆开。
- 把该章节的问题按**同学实际遇到的先后顺序**重新分成 3–4 个部分（例如：谁要做 → 什么时候 → 怎么做 → 做完之后），每部分一张章节卡。
- **答案只能来自原文。** 改写处、合并处、从其他章节补进来的句子，都要在交付时逐条标出，请用户核对。
- 结构固定为：冷开场（一句钩子，3 秒内画面要动起来）→ 封面 → [章节卡 → 问答镜头 × n] × 部分数 → 划重点 → 片尾免责声明卡。

## 3. 建立一集

```bash
.venv/bin/python tools/new_episode.py <id> --episode 第六期 --tag 补测篇 \
  --subtitle "南昌大学《学生体质健康标准》Q&A" --title "<完整标题>" --brand <品牌名>
```

- `<id>` 用小写字母，例如 `bk`。
- 脚本会从 `video/src/episodes/_template/` 复制出 `video/src/episodes/<id>/`，并注册为合成 `EP-<id>`。
- 期数、标题和品牌写在这一期的 `episode.json` 里。
- 完整的参考范例：`video/src/episodes/bu/`（补测篇）和 `hm/`（缓免测篇）。

### 3.1 配音稿 `narration.json`

- 每个镜头一条（id 如 `b01`…），口语化、短句。问句用问号，配音会自动上扬；强调句会自动放慢。
- **数字写成汉字读法**，字幕里再映射回阿拉伯数字：`"subs_map": {"六十分": "60分", "七十二小时": "72小时"}`。
  - 年份写成「二零二四级」；号码按组读，例如「三九二、四六七、五四四」。
- 某句后要留长停顿时，写 `"style": {"0": [3, 6, 1.1]}`，三个数依次是：第 0 句的语速%、音调 Hz、句后停顿秒数。
- 默认声音是晓伊（`zh-CN-XiaoyiNeural`），用户可以换成 edge-tts 的其他中文声音。

### 3.2 镜头表 `shots.json`

每个镜头写成 `{"id", "min"(最短秒数), "hold"(配音后留白秒数), "section"(配乐段落)}`。

配乐段落有这些：

| 段落 | 用在哪里 |
|---|---|
| `tense-intro` | 冷开场：滴答声加低音，结尾用军鼓引入 |
| `cover` | 封面，全乐队 |
| `chapter` | 章节卡 |
| `qa` | 问答，轻节奏 |
| `calm` | 舒缓 |
| `tense` | 严肃的规则 |
| `finale` | 划重点，全乐队 |
| `end` | 片尾，长和弦 |

没有配音的镜头（片尾卡）不写进 `narration.json`，只在 `shots.json` 里给 `min`。

### 3.3 生成声音、时间轴、配乐

```bash
tools/audio.sh <id>            # 全部重做
tools/audio.sh <id> b04 b07    # 只重配某几句，时间轴和配乐会跟着更新
```

检查输出，每句都要是 `char alignment 100%`。时间轴按 112 BPM 对齐节拍，写进 `timeline.json`，画面和配乐都读它。

### 3.4 镜头 `shots.tsx` 与 `Film.tsx`

- 用 `cue("<镜头id>", "说到的词")`，让画面在说到那个词时出现；用 `beat(id, n)` 卡节拍。词必须是 narration 里的原文（汉字读法）。
- 每个问答镜头由三部分组成：
  - `QHeader`：问题；
  - `Answer`：一句话答案，在说出答案时弹出；
  - 一个**把答案演出来的画面**，例如流程节点、对比卡、成绩卡、时间轴、象形小人动作、真实截图放大框。音效卡在动作上（`Sfx`）。
- 布局网格：

  | 区域 | 位置 |
  |---|---|
  | 品牌标签 | 左上，y≈36–130 |
  | 问题标题 | y=170 |
  | 答案条 | y=300 |
  | 画面区 | y=390–950 |
  | 字幕条 | y≥988，不能放东西 |

  左右各留至少 150px 边距。
- `Film.tsx` 里要填：
  - `PART`：右上角的章节名；
  - `DARK`：深色底的镜头（HUD 改用浅色）；
  - `noTab`：封面和片尾卡不显示左上标签；
  - 转场方式：`columns` / `rows` / `iris`，章节卡用 `rows`。
- 新的小人动作，先在 `Figure.tsx` 的 `POSES` 里加姿势，用 `PoseSheet` / `ItemSheet` 渲染静帧检查过再用。

## 4. 自查（每次交付前必须做）

```bash
tools/review.sh <id>     # 自动切到这一期的品牌 → 半分辨率试渲染 → 截帧拼图，结果在 out/review/<id>/sheet_*.jpg
```

打开每一张拼图逐镜检查，对照 `docs/CHECKLIST.md`：

- 文字溢出、换行；
- 元素相撞；
- 留白；
- 小人姿势，动作是否重复；
- 答案有没有被画出来；
- 事实是否与原文一致。

发现问题就改，改完再截帧确认。要单独看某一帧：

```bash
python3 tools/brand.py for <id>
cd video && npx remotion still EP-<id> /tmp/x.png --frame=<帧号> --scale=0.5
```

帧号用 `timeline.json` 里的 `from` 和 `frames` 算。

## 5. 导出

```bash
tools/render.sh <id> "<完整标题>"
```

导出前会自动切到这一期的品牌。得到这三个文件：

- `out/<标题>.mp4`：1080p，响度 −14 LUFS；
- `.srt`：字幕；
- `_压缩版.mp4`：适合发微信。

完整版渲染约 10 分钟，放到后台运行。

## 6. 交付时告诉用户

- 文件位置和时长。声音请用户亲自听，你听不到。
- 内容结构表：部分 → 问题 → 画面。
- **需要核对的清单**：所有改写、合并、补充；示意数据（例如成绩卡上的分数是示意，要标「示意」）；原文和 APP 的矛盾。

## 7. 修改

- **改字幕或配音文字**：改 `narration.json` → `tools/audio.sh <id> <镜头id>` → 检查 → 重新导出。
- **改品牌**：改 `brands/<品牌名>/brand.json`，用这个品牌的所有期都会跟着变。
- **换这一期的品牌**：改这一期 `episode.json` 里的 `brand`。
- **通用意见**：用户的新意见如果对每一期都适用，追加到 `docs/LESSONS.md`。
- **预览**：先运行 `python3 tools/brand.py for <id>`，再在 `video/` 里运行 `npx remotion studio`。它会一直运行，放到后台，把网址告诉用户；有内置浏览器就直接打开 `/EP-<id>`。
- **继续上次的**：先看 `video/src/episodes/<id>/` 里有哪些文件、有没有 `timeline.json`、`out/` 里有没有成片，判断做到哪一步，再接着做。
