# 公众号推文排版（模板库）

完整流程分五步：选模板 → 列材料 → 用户发材料 → 生成网页并改到满意 → 有新版式时问要不要存进模板库。

- 一篇推文就是一个 Markdown 文案文件，交给 `scripts/build.py` 后得到粘贴用的 HTML 和 `预览.html`。
- 模板库在 `templates/<模板名>/` 下，每个模板是一个文件夹。
- 模板的样式数值和图片（公众号图床链接）原样沿用，不要自创样式，也不要换图。

## 第一步：选模板

如果用户第一条消息已经说清用哪个模板，并带来了材料，就跳过这一步，直接进入第四步。

1. 运行下面的命令生成「模板一览」网页，并打开给用户看。在桌面 App 里用浏览器面板打开；在终端里用 `open`（Windows 用 `start`）。
   ```bash
   python3 <本 skill 目录>/scripts/gallery.py -o 模板一览.html
   ```
2. 用选择题问用户（有 AskUserQuestion 就用它，没有就用文字列出编号）：
   - 已有模板最多列 3 个，选项写成「编号 名称（公众号）」；
   - 最后一个选项固定为「照一篇新推文做（导入新模板）」；
   - 模板超过 3 个时，告诉用户可以在「其他」里填一览页上的编号。
   - `gallery.py --list` 能在终端列出全部编号。

## 第二步：列出需要的材料

一条消息说完，然后等用户在**同一个对话的下一条消息**里发来。不要叫用户另开对话。

| 选的是 | 需要的材料 |
|---|---|
| 已有模板 | ① 文案文件，以及用其中哪一部分 ② 视频（可选，可以多段）③ 推文完整标题（片头上有就可以不给）④ 口径：文案里说法矛盾的地方以哪个为准 |
| 照一篇新推文做 | 上面全部，再加：⑤ 参考推文的链接（已发布的文章；草稿就导出正文代码）⑥ 新模板叫什么名字、属于哪个公众号 |

## 第三步：做模板（只有选了新版式才做）

按 `references/NEW-LAYOUT.md` 操作：

1. 用 `scripts/fetch_article.py` 取参考推文的正文代码；
2. 用 `scripts/outline.py` 拆出它的结构；
3. 在用户的工作文件夹里新建 `./推文模板/<模板名>/`：
   - 只换颜色、图片：写 `template.json`；
   - 结构也不同：再加 `components.py`；
4. 用新模板排这次的文案，逐屏和参考推文对比截图，改到用户认可为止。

这一步可能要来回几轮，先跟用户说清楚。

## 第四步：排版、生成、审稿

1. **认视频**：分不清哪个视频对应哪篇时，抽片头帧看标题（`ffmpeg -ss 1 -i 视频.mp4 -frames:v 1 片头.png`），再抽几帧确认讲的是哪些问题。
2. **写文案文件**：格式见 `references/FORMAT.md`，示例见 `templates/jwdy/example.md` 和 `examples/格式示例.md`。
   - 用新模板时，在信息区写 `模板: 推文模板/<模板名>`。
   - **问题、答案逐字照抄原文。** 只允许这几种排版处理：
     - 去掉数字与汉字之间的空格；
     - 长答案在分号处分段，列表按项换行；
     - 补句末标点；
     - 用 `**加粗**` 标出重点。

     其他任何改动都要在交付时逐条列出，请用户确认。
   - 按原文顺序切成 3–5 个分区，分区标题写成「X篇｜a、b、c」。只有一个问题的分区，直接写主题。
   - **头图标题和系列统一**：和视频片头、往期封面用同一种写法，最多三行，例如 `头图: 南昌大学 / 《学生体质健康标准》Q&A / （体质测试篇）`。封面标题写在 `封面:`，例如 `南昌大学 / 《学生体质健康标准》 / Q&A / （体质测试篇）`。
   - **结尾写 `## 最后再次划重点`**：
     - 用两段话归纳本篇要点，只能从正文归纳，不加新信息；
     - 最后一句写「具体安排以……通知为准」，再加一句祝愿。
     
     总结是新写的，交付时要请用户核对。
3. **生成**：
   ```bash
   python3 <本 skill 目录>/scripts/build.py 文章1.md 文章2.md -o 输出目录
   ```
   终端打印的 ⚠️ 必须清零。只检查不生成时加 `--check`。
   再生成封面：
   ```bash
   python3 <本 skill 目录>/scripts/cover.py 文章1.md 文章2.md -o 输出目录
   ```
   每篇得到两张：`封面_<文件名>.png`（上传用，2.35:1 用整张，1:1 框住正中间的正方形）和 `_1比1.png`（正中那块）。要用 Chrome 或 Edge 截图。
4. **自检**：打开 `预览.html`，页面会在 360、375、390、430 四种宽度下自动检查，结果显示在每篇上方。有浏览器工具就自己逐屏截图看一遍。
5. **交付**，告诉用户：
   - 生成了哪些文件，包括封面；
   - 哪个视频对应哪篇推文，每篇的完整标题；
   - 你加了什么：分区标题、加粗、祝福语；
   - 需要用户确认什么：文案矛盾、两行放不下的问题、改动过的句子；
   - 发布步骤：「复制排版」→ 公众号后台新建图文，在正文里粘贴 → 在黄色虚线框处插入视频，再删掉虚线框 →「复制标题」填进标题栏 → 上传封面（2.35:1 选整张，1:1 框中间）→ 用手机预览确认 → 交给负责发布的人。
6. 按用户的意见修改、重新生成，直到满意。

## 第五步：存进模板库（只有这次做了新模板才问）

用现成模板做的，不要问。

做了新模板的，交付完问：「这次的版式要存进模板库吗？存进去以后大家都能选。」用户同意后，按 `references/CONTRIBUTE.md` 提 PR：

1. 补齐模板文件：示例、缩略图、快照、来源和版权说明；
2. 跑回归检查，旧模板的生成结果一个字节都不能变；
3. 把改动清单给用户看，用户确认后再提 PR。

**只提 PR，由维护人审核合并，绝不直接推到 main。**

## 硬性要求（来自用户审稿，逐条遵守）

- **问题标题最多两行，绝不能出现三行、四行**（用户原话：“很丑，最多两行”）。
  - 每行不超过模板 `limits` 里的字数（默认 12 字，这样 360px 宽的安卓手机也不折行）。
  - 手动断行，断在逗号、问号或语义停顿处，例如 `### 测试过程中， / 感觉身体不适，怎么办？`。
  - 原问题两行放不下时，不要拆成三四行，也不要自己删字改写。列给用户，由用户精简；用户给了写法再填进去。
- 分区标题不超过 `limits` 里的字数（默认 15 字）。
- **头图标题和系列统一**（老师审稿意见）：和视频片头、往期封面同一种写法，不要自己简化。
- **结尾必须有「最后再次划重点」总结**（老师审稿意见）：只从正文归纳，最后写「具体安排以……通知为准」。
- **每篇都要配封面**（老师审稿意见）：用 `scripts/cover.py` 按模板的往期样式画，不要用视频截图当封面。
- 两端对齐时，QQ 号、网址这类长串会把上一行撑出大空隙。生成器会自动让这类段落可以在串中间断行；网址再用反引号包住收紧字距，需要时用行末 `\` 让它单独成行。
- 视频位置放黄色虚线占位框，由用户在公众号编辑器里插入视频。不要尝试用代码嵌入视频。
- 只用行内样式和公众号图床图片（`mmbiz.qpic.cn`）。公众号会过滤 `<style>`、class、`position`、脚本和外链图片。
